# VKMDownload

一个用 Go 写的多连接下载管理器（IDM 风格）：**下载引擎 + Wails 桌面界面 + 浏览器扩展**。

把一个文件切成多段并行下载，支持断点续传；引擎自带一个"恶意服务器"测试工具，
用来验证它在真实网络里遇到的各种坑（服务器谎报支持 Range、中途断线、谎报文件大小……）
时不会悄悄给你一个坏文件。

> **状态**：引擎、桌面应用、浏览器扩展均已完成并通过验证。

---

## 功能

### 引擎

- **多连接分片下载** —— 每段一个独立 HTTP 请求，各自写入文件的不同偏移
- **动态分段** —— 某个 worker 空闲时，把最长的剩余段对半切开交给它，不让慢连接拖住整体
- **断点续传** —— 进度写进 sidecar（`.vkmdownload.json`），暂停 / 崩溃后可继续（取消会丢弃断点）
- **一致性校验** —— 用 ETag / Last-Modified 判断服务器端文件是否变过；变了就重下，不拼接
- **自适应降级** —— 服务器不支持 Range 时自动退回单连接流式下载
- **重试与退避** —— 网络中断、5xx、429 按指数退避重试；4xx 直接失败不做无用功
- **全局速度上限** —— token bucket，所有任务共享一个上限，而不是每个任务各自限速
- **故障注入测试服务器** —— 可模拟断线、假 Range、谎报 Content-Length、403、chunked 等

### 桌面界面

- 任务列表带实时进度、速度、分片数，**列宽可拖动并会记住**
- 暂停 / 继续 / 取消，**暂停保留断点可续传**
- **每次下载先问保存位置**（默认开，可关；关掉弹窗等于放弃这次下载）
- **按类型自动整理**（默认关）：自动到来的下载完成后按扩展名搬进分组文件夹（Programs / Documents / Archives，可改可加组），手动创建的不动
- **按文件类型筛选**（扩展名按钮由实际出现的类型生成，不是固定表）
- **批量操作**：全部开始 / 全部停止 / 计划下载（跑完所有任务后响铃或关机）
- **删除当前列表**（按筛选范围），带确认；下好的文件不动，没下完的半成品跟随清理
- 剪贴板链接监控（可选自动开始 / 先确认）
- 关闭窗口最小化到托盘，下载不中断
- **自动更新**：有新版时顶部出横幅，一键下载、校验、暂停任务后重启生效，也可在设置页手动检查
- 深色界面，中文

### 浏览器扩展

- 把浏览器的下载**交给 VKMDownload**，不再让浏览器自己下
- 右键菜单「用 VKMDownload 下载」
- **Brave / Edge / Chrome / Opera / Vivaldi 共用一套代码**（Chromium 系）
- 支持**体积阈值**（默认小于 1 MB 交给浏览器）和**站点排除**
- 所有开关都在**应用设置里**，扩展每次拦截前会问应用，**改完立刻生效、不用重装**

## 下载安装

### 用现成的

到 [Releases](../../releases) 下载：

| 文件 | 说明 |
|---|---|
| `VKMDownload.exe` | 主程序。**双击即可运行，无需安装** |
| `VKMDownload-extension.zip` | 浏览器扩展，解压后加载 |

> **Windows 会提示"已保护你的电脑"**：因为 exe 没有代码签名证书。点**「更多信息」→「仍要运行」**。
> 这是未签名程序的正常提示，不是病毒警告。

### 浏览器扩展怎么装

**这个扩展没有上架应用商店**，需要手动加载（约 1 分钟）：

1. **先启动 VKMDownload**（扩展要问它该不该接管，它得在运行）
2. 打开浏览器的扩展管理页：

   | 浏览器 | 地址 |
   |---|---|
   | Brave | `brave://extensions` |
   | Edge | `edge://extensions` |
   | Chrome | `chrome://extensions` |
   | Opera | `opera://extensions` |

3. 打开右上角的**「开发者模式」**
4. 点**「加载已解压的扩展程序」**，选择解压出来的目录本身（能看到 `manifest.json` 的那层）

> **⚠️ 如果装过 IDM 或其它下载器的扩展，先把它关掉。** 两个扩展都监听同一个下载事件，
> 会互相抢，结果是下载失败或下载两遍。
>
> **应用默认每次下载都会问保存位置**，这时请关掉浏览器自带的"下载前询问保存位置"，
> 否则同一个文件会弹两次（浏览器一次、应用一次）。
>
> **每次浏览器启动会提示「请停用开发者模式扩展」** —— 这是 Chromium 的固定行为，
> 只有上架商店才能消除。点掉即可，不影响使用。

细节见 [extension/README.md](extension/README.md)。

### 软件更新

有新版时，程序顶部会出现横幅。点**立即更新**：新版在后台下载并做哈希校验，完成后自动暂停全部任务、换文件、重启——重启后任务都在，可继续下载。点**不再提示**会告诉你去哪里手动更新：设置页拉到最底部 → 软件更新 → 检查更新。

更新包就是 Releases 里的 `VKMDownload.exe`，不走别的来源。

### 从源码构建

需要 **Go 1.24+**、**Node.js**、**Wails v2**，以及 Windows 上的 **WebView2** 运行时（Win11 自带）。

```bash
# 桌面应用
cd desktop
wails build            # 产出 build/bin/VKMDownload.exe

# 命令行版本
go build -o bin/vdl.exe ./cmd/idm
```

## 命令行

引擎也能单独用（`cmd/idm`）：

```bash
go build -o bin/vdl.exe ./cmd/idm

vdl get https://example.com/big.zip -o D:\Downloads -conns 8   # 下载
vdl info https://example.com/big.zip                           # 先看服务器能力
vdl bench https://example.com/big.zip -conn-list 1,2,4,8,16    # 对比连接数
vdl get https://example.com/big.zip -resume                    # 断点续传
```

| 参数 | 默认 | 说明 |
|---|---|---|
| `-conns` | 8 | 并发连接数，1 表示禁用分段 |
| `-o` | 服务器建议的文件名 | 输出文件或目录 |
| `-min-segment` | 1 MiB | 最小分片大小，小文件不会被切碎 |
| `-reserve` | 512 KiB | worker 一次认领多少字节 |
| `-chunk-size` | 128 KiB | 读写缓冲，超 256 KiB 会被钳住 |
| `-H` | | 附加请求头，可重复，如 `-H 'Cookie: a=b'` |
| `-proxy` | | 代理地址，留空则读环境变量 |
| `-insecure` | 关 | 跳过 TLS 证书校验（仅排障用） |
| `-timeout` | 无 | 整次下载超时，0 表示不限 |
| `-resume` | 开 | 断点续传，默认即开 |
| `-json` | | 以 JSON 输出结果 |

## 实测性能

对本地测试服务器（32 MiB，每连接限速 2 MiB/s）实测，每一级都做了**逐字节内容校验**：

| 并发连接 | 耗时 | 吞吐 | 相对单连接 |
|---:|---:|---:|---:|
| 1 | 16.0s | 2.0 MiB/s | 1.00x |
| 2 | 8.0s | 4.0 MiB/s | 2.00x |
| 4 | 4.0s | 8.0 MiB/s | 3.99x |
| 8 | 2.1s | 15.0 MiB/s | 7.50x |
| 16 | 1.3s | 25.4 MiB/s | **12.68x** |

为什么要在本地做限速测试：loopback 上 RTT 几乎为零，不限速的话单连接就能跑满，
多连接的优势完全看不出来。限速后才复现了真实互联网上"多连接绕过单连接限速"的场景。

## 设计要点

### HTTP/2 是被**故意**关掉的

`internal/engine/transport.go` 把连接固定到 HTTP/1.1（`TLSNextProto` 设为空 map）。
这不是风格选择，而是分片下载能加速的**前提**：HTTP/2 会把同一域名的所有请求
复用到**一条** TCP 连接上，于是 16 个 Range 请求挤在同一条流里，一起撞上那条流的
拥塞窗口——看起来并行，实际等于没并行；更糟的是，按连接限速的服务器会把 16 个
"并行"流一起限速。HTTP/1.1 下一条连接只承载一个进行中的请求，N 个并发 Range
请求必然是 N 条独立 TCP 连接。

### 磁盘上的三件套

```
big.zip                    成品
big.zip.vkmdownload.part     半成品数据（各 worker 用 WriteAt 写入自己的偏移）
big.zip.vkmdownload.json     分段进度 + ETag + 总大小
```

全部下载完成后，`.part` 被重命名为成品名，`.json` 被删除。
续传前会校验链接地址、ETag / Last-Modified / 总大小，任何一项不一致就丢弃重来——
把两次不同版本的数据拼在一起，会得到一个长度完全正确、内容却是坏的的文件。

### 分片进度用两个计数器，不是一个

这是踩过坑的地方，值得单独说。

一开始只用一个计数器，它同时表示"已预留"和"已写入"。多个 worker 会对它做
`+= n`（认领）和 `-= n`（失败退回），这些加减**交错**之后，最终值取决于执行顺序，
而不再等于真实落盘的字节数。一旦偏高，下一个请求的偏移量就会跳到没人下载过的位置，
那一段就永远被跳过——而**文件长度依然是正确的**，任何长度校验都抓不到。

现在拆成两条独立轨道：

- `Reserved` 只用来防止两个 worker 抢同一段；
- `Written` **只**在数据真正 `WriteAt` 落盘之后才推进，并且是唯一决定"下一个请求位置"的量。

这样无论并发如何交错，请求偏移量都只反映真实写进磁盘的字节，物理上不可能跳过空洞。

### 删除记录：成品不动，半成品跟随

列表里的删除按钮、批量删除、清理失败记录，删的都是记录；已经下好的成品文件**永远不动**（除非单条删除时明确勾了删文件）。
没下完的任务不一样：它的 `.part` 和 sidecar 没了记录就永远续不上，只会变成垃圾，
所以删记录时自动带走——同链接重下从头开始。确认框里会明确写出这一点。

### 测试服务器比真服务器更"坏"

`testsrv/` 是一个可编程的恶劣服务器：`-fake-range` 会自称支持 Range 却总是返回 200；
`-ignore-if-range` 无视 `If-Range` 照样返回 200；`-drop-after` 在指定字节后硬断连接；
`-drop-prob` 按概率随机断流；`-lie-content-length` 谎报长度；
`-no-range` 完全不提供 Range；`-require-cookie` 不给 cookie 就 403。
引擎的探测逻辑之所以**不信** `Accept-Ranges` 头、只信实测的 206 响应，就是被它逼出来的。

### 扩展为什么不用 native messaging

IDM 那种做法要装一个 native messaging host，还要为每家浏览器写各自的注册表项，
任何一步失败都会**静默不工作**。这里应用自己开一个**只监听 `127.0.0.1`** 的端口，
扩展扫描 18888–18898 自动找到它——用户只需要装扩展，不用装第二个程序。

**安全**：端点拒绝来源不是浏览器扩展的请求。跨域 POST 即使页面读不到响应也会被送达，
所以没有这道检查的话，你访问的任何网页都能往下载队列里塞任务。
浏览器建议的文件名也会被削到最后一个路径段，否则远程服务器就能决定文件落在哪。

## 测试

```bash
go test ./...            # 全部测试
go test -race ./...      # 并发正确性（推荐，历史上抓出过真 bug）
VKMDOWNLOAD_DIAGNOSE=1 go test ./internal/engine -run Diagnose -v   # 长时间压力诊断
```

排障时打开引擎的详细日志：

```bash
VKMDOWNLOAD_DEBUG=1 vdl get <url>               # 打到 stderr
VKMDOWNLOAD_DEBUG=%TEMP%\vkm-trace.log vdl get <url>    # 打到文件
```

应用侧的日志在 `%APPDATA%\VKMDownload\vkmdownload.log`。

## 已知边界

- **不支持视频嗅探**：IDM 的招牌功能之一，但那是另一个项目规模（m3u8/DASH 解析 + TS 合并）
- **Firefox 扩展尚未适配**：扩展 API 与 Chromium 系不同，需要单独一套
- **扩展未上架商店**：因此每次浏览器启动会有开发者模式提示
- **没有代码签名**：exe 会触发 Windows SmartScreen 提示
- **需要登录的网盘链接**（如 Google Drive 私有文件）无法下载 —— 应用没有浏览器的登录态。
  会明确提示这一点，而不是把登录页当成文件存下来
- **exe 属性页里看不到版本号**：Wails v2.16.0 生成的资源块不完整 —— 同一块里的图标是正常的，
  但版本字段没写进去。程序自己报告的版本是对的（设置页底部可见）。不影响功能。
- 引擎只处理直链文件下载

## 命名

统一使用 `VKMDownload`（用户可见名）与 `vkmdownload`（module 名、文件后缀、环境变量前缀 `VKMDOWNLOAD_`）：

| 位置 | 命名 |
|---|---|
| Go module | `vkmdownload` |
| `.vkmdownload.part` / `.vkmdownload.json` | 未完成的半成品与续传进度 |
| `VKMDOWNLOAD_DEBUG` 等环境变量 | 引擎日志与诊断开关 |
| 数据目录 `%APPDATA%\VKMDownload` | 设置与任务列表 |
| `vkmdownload.column-widths` | localStorage 列宽键 |

**面向用户的名字**（窗口标题、可执行文件、侧栏、开始菜单、发布包）全部是 **`VKMDownload`**。
