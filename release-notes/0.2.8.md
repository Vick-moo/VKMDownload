# VKMDownload 0.2.8

- 修复：连续快速点「暂停 → 继续」可能把任务变成「已取消」，甚至删掉刚起步的半成品
- 修复：设置页改一项配置存在数据竞争，改动可能丢失
- 修复：失败提示会把下载链接里的私密参数写进记录文件并显示在屏幕上
- 修复：自动更新失败后桌面上没有程序在跑；「还原旧版本」在某些状态下永远无效
- 修复：服务器返回错误数据时卡两分半才报错；拒收探测请求的服务器白等 3 秒半
- 修复：超长中文文件名被截断成乱码
- 修复：浏览器插件会把登录信息交给本机任何冒充程序；任何插件都能指挥下载器
- 隐私：任务记录与日志不再长期保存可用的签名链接；未完成任务的登录信息改为加密存放
- 新增：设置里可关闭「启动时自动检查更新」，并有「隐私」页可查看与清除本机数据
- **扩展有改动，升级后请到浏览器扩展页点一次「重新加载」；应用与扩展请一起更新**

## 详细说明

### 需要注意的兼容性

这一版改变了应用与扩展之间的认证方式，**两端必须一起更新**：

- 应用 0.2.8 + 扩展 1.0.3：正常。
- 应用升级了、扩展还是 1.0.2：扩展拿不到配对密钥，会显示「应用没有运行」，
  下载仍由浏览器自己完成（不会丢文件，但也不再接管）。
- 扩展升级了、应用还是 0.2.7 或更早：同样按「应用没有运行」处理。

重新加载扩展的位置：浏览器地址栏进 `chrome://extensions`（Edge 为 `edge://extensions`），
找到 VKMDownload 点「重新加载」。若仍显示未运行，打开扩展弹窗点「重新配对」。

### 这一版修了什么

**下载列表（manager）**

- 快速「暂停 → 继续」时，上一轮的收尾逻辑会把新一轮的状态盖成「已取消」，取消动作还会
  删掉刚起步的半成品。现在每一轮都有独立编号，收尾时必须对号。
- 任务在启动或收尾瞬间被删除时，进度或完成事件会写回已删除的记录，屏幕上「复活」一行。
- 设置页修改配置与后台读取存在数据竞争（`-race` 实测），改动可能丢失；现在进出都深拷贝，
  保存失败会回滚。
- 「N 秒后自动重试」的提示会存进记录文件，重启后闪一条早就不成立的提示；现在暂停、取消、
  重启恢复三处都会清掉。
- 失败提示缺 429/5xx 分支，会把带完整链接（含签名参数）的原始错误写进记录并显示。
- 计划下载被无关任务干扰：跑计划时新加一个暂停任务，完成提示音和关机被静默跳过。
- 迟到的进度事件会把「失败」的行重新画成「下载中」。
- 已完成/已取消/已失败超过 90 天的记录在启动时清理。

**自动更新**

- 备份改为一律复制（不再用硬链接），回滚与清理不再依赖链接语义。
- 换文件失败、或新版校验失败时，把旧版重新拉起来——以前会让桌面上一个程序都不剩。
- 「还原旧版本」在程序文件已被改名/缺失时也会成功。
- 连点两次「立即更新」不会再写坏同一个下载文件。
- 更新过程中拒绝开始新的下载。
- 助手侧按记录的大小与 SHA-256 复核新版文件（以前只查「开头是 MZ、大于 1MiB」）。
- 自更新下载的句柄会正确关闭并在校验前落盘（以前失败分支的「已丢弃」是假话）。
- 60 秒握手判据改为「等待期间出现过窗口即视为已启动」，避免慢启动被误判回滚。
- 确认更新前校验运行中的正是记录里那个新版本；没有哈希时不删备份；只有真删掉备份才删标记。
- 应用与助手之间用一个跨进程锁串行写状态文件，临时文件名带 pid。
- 「已是最新」不再记成失败。

**引擎与命令行**

- 服务器返回的数据范围对不上时立刻失败（以前最长假死 151 秒）。
- 服务器拒收 HEAD 时只发一次（以前白等约 3.5 秒）。
- 文件名按字符截断，中文/emoji 不再被切断；支持 `filename*=` 的 UTF-8/Latin-1 写法。
- 没有校验值（ETag/Last-Modified）时拒绝续传，避免把两个版本拼在一起。
- 「检查文件大小」开关以前没有任何代码读取，现在真的会检查。
- 进度记录写失败会报告并计数，不再悄悄失败。
- 限速在 32 位构建上会溢出失效，已修；剩余时间不再出现荒谬数值。
- 命令行新增 `-limit`；重复 `-H` 不再被拼成一条畸形头；文件大小未知时显示「unknown」。

**浏览器扩展**

- 新增每次安装生成的配对密钥：扩展必须现场证明对方持有该密钥，才发送网址与 Cookie；
  拿不到密钥时按「应用未运行」处理，绝不发给未验证的响应方。
- 每次交接前都重新验证（不再信任缓存端口）。
- 先验证、再读 Cookie；本机与内网地址不读 Cookie。
- 隐身模式下的下载不再接管。
- 应用拒绝接收时不再取消浏览器原有的下载（以前会丢掉进度、来源页和保存目录）。
- 来源页只发送「协议 + 主机 + 路径」，搜索词/文档 ID 不再进入任务记录。
- 通知与提示统一脱敏（网址只留主机+路径、去控制字符、超长截断）。
- 不接管其他扩展发起的下载。
- 弹窗的开关在后台不可达时会恢复按钮并给出提示（以前会永久变灰）。
- 交接后若浏览器扩展被系统回收，下次启动会补做取消，避免同一文件下两份。

**隐私**

- 已完成任务的记录不再保留完整链接与登录信息；日志写入前统一脱敏。
- 旧版本写下的明文记录与日志在启动时清洗一次，包括损坏副本与临时文件。
- 未完成任务的登录信息用 Windows DPAPI 加密：拷到别的电脑、备份同步、换账户都解不开；
  但以同一用户身份运行的恶意程序仍能解密（这一点写在 `PRIVACY.md` 里）。
- 新增产品级 `PRIVACY.md`，逐项说明存了什么、发到哪、怎么清、以及明确的取舍。
- 本机接口：只接受回环 Host；写操作要求扩展的签名；进程身份校验改为查不到即拒绝
  （以前可用 `127.0.0.2` 或「复制一个签名程序改名」绕过）。
- 新增「隐私」设置页：显示本机保留了多少条记录/日志，并提供一键清除（不会删已下载的文件）。

### 安装

- 下载 `VKMDownload.exe`，放到一个可写目录直接运行（绿色版，无需安装）。
- 没有代码签名，首次运行 Windows SmartScreen 会提示；选「更多信息 → 仍要运行」。
- 扩展：`chrome://extensions` 开启开发者模式，「加载已解压的扩展程序」选择仓库中的
  `extension/` 目录。**这一版必须重新加载**。

### 已知限制：部分站点限制下载速度

有些文件站会故意限速免费下载，引导用户付费提速。这类站点通常拒绝多连接请求（404/403/429），只接受单连接顺序读取。

**当前版本不支持这类站点**：遇到时任务可能失败或停在「下载中」不动。

**解决方法**：把该任务的**连接数改为 1**，再重新开始下载。单连接速度受限，但可以下完。

### 已知取舍

- 未完成任务的登录信息虽然加密，但以同一用户身份运行的恶意程序仍可解密。
- 断点续传记录（下载文件旁的 `*.vkmdownload.json`）含带签名的下载地址；下载完成后删除。
- 日志不脱敏文件名与本机路径（网址查询串与 User-Agent 已处理）。
- 设置里的代理地址如果带用户名密码，会以明文存在 `config.json`。
- 首次配对仍依赖「应用端口没有被别的程序抢先占用」；更强的方案需要系统级注册，暂未实现。
