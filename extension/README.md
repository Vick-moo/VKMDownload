# VKMDownload 浏览器扩展

把浏览器里的下载交给 VKMDownload，不再让浏览器自己下。

## 支持哪些浏览器

**Brave、Edge、Chrome、Opera、Vivaldi** —— 所有 Chromium 内核的浏览器**共用这一套代码**。

Firefox 需要单独适配（扩展 API 不同），目前不支持。

隐私（扩展经手哪些数据、存到哪）：见 [PRIVACY.md](PRIVACY.md)；
桌面端存了什么、发到哪，见产品级说明 [../PRIVACY.md](../PRIVACY.md)。

---

## ⚠️ 装之前：先关掉 IDM 的扩展

如果你装过 **IDM Integration Module**（或其它下载器的扩展），**先把它关掉**。

两个扩展都监听同一个下载事件，会互相抢：

- 两个都试图取消 → **下载直接失败**
- 一个抢到、另一个把任务"还"给浏览器 → **重复下载**

在扩展管理页把它右侧的开关点成灰色即可，**不用卸载**。

## 安装

> **这个扩展没有上架应用商店**，所以要手动加载。步骤不难，但**每次浏览器启动会提示「请停用开发者模式扩展」** —— 这是 Chrome 内核的固定行为，**点掉即可，不影响使用**。

1. **先启动 VKMDownload**（扩展要问它该不该接管，它得在运行）
2. 打开浏览器的扩展管理页：

   | 浏览器 | 地址 |
   |---|---|
   | Brave | `brave://extensions` |
   | Edge | `edge://extensions` |
   | Chrome | `chrome://extensions` |
   | Opera | `opera://extensions` |

3. 打开右上角的**「开发者模式」**
4. 点**「加载已解压的扩展程序」**
5. 选择**本目录**（`extension`，不是它的上级目录）

装好后工具栏会出现牛头图标。**每个浏览器要各装一次**（用同一份文件）。

## 使用

**接管下载**：点下载链接时，扩展先把任务交给 VKMDownload，应用收下后浏览器那边的下载才取消。默认**只接管 1 MB 以上的文件**（原因见下）。

**右键菜单**：在链接、图片、视频、音频上右键 → **「用 VKMDownload 下载」**
（选中一段文字作为地址后右键也可以。右键菜单**不受 1 MB 限制**，是你明确要求的。）

---

## 在哪里改设置

**在应用的「设置 → 浏览器扩展」里**，四个选项：

| 设置 | 作用 |
|---|---|
| **接管浏览器下载** | 总开关。关掉后浏览器恢复自己下载，扩展仍然装着但不再拦截。 |
| **验证浏览器身份** | 默认开。每次接管先确认对方是正版签名的浏览器，不是冒充的程序。每次下载约多花 1 毫秒。关了就是秒接，但本机任何程序都能冒充扩展下发任务。 |
| **小于此大小交给浏览器** | 默认 1 MB。填 0 = 全部接管。 |
| **不接管的网站** | 一行一个域名。填 `example.com` 会同时排除 `www.example.com` 和 `cdn.example.com`。 |

**为什么默认有 1 MB 下限**：浏览器自己也在下载很多东西 —— 自动更新包、网页图标、PDF 里的图片。一个"什么都抢"的扩展会让这些全部变成下载任务，这是最容易让人直接卸载的做法。

**改完立刻生效**，不用重装扩展（原理见下）。

工具栏那个牛头图标里的开关和这里是**同一个设置**，只是快捷入口 —— 两边不会打架。

## 它是怎么工作的

```
浏览器扩展  ──HTTP──▶  127.0.0.1:18888  (VKMDownload 内置)
      │                        │
      │  ① 下载前先问：          │
      │     "现在该不该接管？"    │
      └───────────────────────▶│
                               │  ② 该 → 创建任务
```

**没有额外的本地程序**。IDM 那种做法要装一个 native messaging host，还要为每家浏览器写各自的注册表项，任何一步失败都会**静默不工作**。这里应用自己开一个**只监听本机**的端口，扩展自动找到它。

**设置为什么在应用里**：扩展**每次拦截前都问应用一句**，所以策略只有一份，改了立刻生效，不需要"改完设置再重装扩展"。

**端口**：默认从 `18888` 开始找，被占用就依次试到 `18898`。扩展扫描同一区间，所以端口被占也不影响。

**安全**：只监听 `127.0.0.1`（外部完全访问不到），并且**拒绝来源不是浏览器扩展的请求** —— 否则你访问的任何网页都能偷偷往你的下载队列里塞任务。
（`background.js` 只检查来源**前缀**是 `chrome-extension://`，所以"加载已解压"时扩展 ID 每次都不同也照样工作。）
另外应用还会**验证来电进程**：顺着连接查到对方进程，exe 名必须是正版浏览器且签名有效，否则拒绝并在日志里点名。来源头是自报的、零成本伪造；进程身份伪造不了（除非往浏览器里注入，那种对手也不差这一个接口）。详见应用设置里的「验证浏览器身份」。

## 故障排查

| 现象 | 原因 / 解决 |
|---|---|
| 弹窗显示「VKMDownload 没有运行」 | 启动应用即可。扩展会在下次下载时重新找到它。 |
| 下载仍然由浏览器完成 | ① 文件小于 1 MB（**这是正常的**）② 接管开关被关了 ③ 该站点在排除列表里 |
| 下载点了没反应 | 应用没运行时，扩展会把下载**交还给浏览器**（不会丢） |
| 装不上，提示清单错误 | 确认选的是 **`extension` 目录本身**，不是它的上级 |
| 每次启动都提示停用开发者模式 | 无法绕过，除非上架商店。点掉即可。 |
| 需要登录的站（网盘私链等）交给应用后 403/跳登录页 | 扩展只在有 host 权限的站点才能读到 cookies（目前仅 `*.google.com` / `*.googleusercontent.com`）。其它站点因缺 host 权限读到的 cookies **静默为空**，应用拿不到登录态就会被拒。先在浏览器里登录该站再试；仍不行就手动建任务。 |
| 下载失败或重复下载 | 大概率是和 IDM 等其它下载器扩展冲突，见上面的警告 |

应用侧的日志在 `%APPDATA%\VKMDownload\vkmdownload.log`。

## 开发时注意

- `background.js` 是 **service worker**，随时可能被浏览器停掉，所以**不能依赖内存状态做关键判断**（`apiBase` 和策略缓存失效后会重新去问）。
- 改完扩展代码，要在扩展管理页点**刷新**按钮。
- 应用侧对应实现在 `desktop/api.go`，测试在 `desktop/api_test.go`。
