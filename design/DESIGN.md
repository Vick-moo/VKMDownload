# VKMDownload 界面设计规范

这份文档是界面实现的**唯一依据**。写组件时照它取值，不要临场发挥颜色和间距——
界面显得业余，通常不是因为不懂设计，而是因为同一个角色在不同地方用了不同的值。

---

## 1. 设计意图

一个**常驻后台、偶尔瞥一眼**的工具。用户打开它，最想知道三件事：

1. 现在在下什么、下到哪了（**一眼**看出进度）
2. 快不快（速度 / 剩余时间）
3. 有没有出问题（失败要显眼，不能藏在角落）

所以视觉优先级是：**进度 > 状态 > 元数据 > 装饰**。
装饰要克制：不要花哨渐变、不要发光边框、不要为了"科技感"牺牲可读性。

深色是**默认且唯一**的主题。它适合长时间挂在后台的窗口，也让进度条的亮色有足够对比度。

---

## 2. 色彩

集中定义为 CSS 变量，放在 `:root`。组件里**只允许**引用变量，不允许写死色值。

### 底色（从深到浅，构成层次）

| 变量 | 值 | 用途 |
|---|---|---|
| `--bg-base` | `#0d0f14` | 窗口最底层背景 |
| `--bg-surface` | `#14171f` | 卡片 / 列表项 |
| `--bg-raised` | `#1a1e28` | 悬浮、下拉、模态 |
| `--bg-hover` | `#222733` | 悬停态 |
| `--border` | `#262c3a` | 常规分隔线、卡片描边 |
| `--border-strong` | `#333b4d` | 输入框聚焦前的描边 |

### 文字

| 变量 | 值 | 用途 |
|---|---|---|
| `--text-primary` | `#e8ecf4` | 标题、文件名 |
| `--text-secondary` | `#9aa4b8` | 说明、次要信息 |
| `--text-muted` | `#626c80` | 时间戳、占位符、禁用 |
| `--text-inverse` | `#0d0f14` | 亮色按钮上的文字 |

对比度要求：`--text-primary` 在 `--bg-surface` 上不低于 **7:1**，
`--text-secondary` 不低于 **4.5:1`。低于这个值就是不合格，不是"风格问题"。

### 强调色与状态色

| 变量 | 值 | 用途 |
|---|---|---|
| `--accent` | `#4c8dff` | 主操作、进行中的进度条 |
| `--accent-hover` | `#6ba0ff` | 主按钮悬停 |
| `--accent-subtle` | `#1e2a44` | 选中行的背景 |
| `--success` | `#3ecf8e` | 完成 |
| `--warning` | `#f0b429` | 暂停、需要用户注意 |
| `--danger` | `#f2555a` | 失败、取消、删除确认 |

**颜色不能是唯一的信息载体**。状态除了颜色，必须配图标或文字——
色盲用户看到的不该是一片灰。这一条在实现状态徽章时是硬要求。

---

## 3. 字体与字号

- 字体栈：`-apple-system, "Segoe UI Variable", "Segoe UI", system-ui, sans-serif`
  （Windows 上优先用 Segoe UI Variable，它是 Win11 的系统字体，小字号更清晰）
- **等宽**（数字列、速度、大小）：`"Cascadia Mono", "Consolas", ui-monospace, monospace`
  —— 所有会变化的数字**必须**用等宽，否则进度百分比跳动时整行会左右抖

| 角色 | 字号 / 行高 | 字重 |
|---|---|---|
| 文件名 / 列表主标题 | 14px / 20px | 500 |
| 正文、按钮 | 13px / 18px | 400 |
| 次要信息（速度、ETA） | 12px / 16px | 400 |
| 徽章、标签 | 11px / 14px | 500 |
| 大号统计数字（顶栏） | 20px / 24px | 600 |

数字统一加 `font-variant-numeric: tabular-nums`，避免宽度变化引起抖动。

---

## 4. 间距

只使用这一套刻度，不要出现 `13px`、`7px` 这种值：

`4 · 8 · 12 · 16 · 24 · 32 · 48`

| 场景 | 值 |
|---|---|
| 图标与文字之间 | 8 |
| 列表项内部纵向 | 12 |
| 列表项内部横向 | 16 |
| 卡片内边距 | 16 |
| 卡片之间 | 12 |
| 区块之间 | 24 |
| 页面四周留白 | 24 |

---

## 5. 圆角与描边

| 元素 | 圆角 | 描边 |
|---|---|---|
| 按钮、输入框、徽章 | 6px | 1px `--border` |
| 卡片、列表项 | 8px | 1px `--border` |
| 模态、大面板 | 12px | 1px `--border-strong` |
| 进度条 | 999px（全圆） | 无 |

焦点态：`outline: 2px solid var(--accent); outline-offset: 2px`。
**不允许**用 `outline: none` 去掉焦点环——键盘用户会失去位置感。

---

## 6. 进度条

下载器的核心元素，单独定规矩：

- 高度 **6px**，全圆角
- 轨道色 `#1e2330`，填充色 `--accent`
- **分片可视化**：每个并发分片在进度条上是一段独立的小块（这是 VKMDownload 的卖点，
  要让用户看得见"8 个连接在同时干活"）。块之间留 1px 间隙
- 完成后填充换成 `--success`
- 暂停时填充换成 `--warning`，并降到 60% 不透明度
- 实时速度超过 0 时，在进度条右端加一道柔和的流动高光（`--accent-hover`，
  1.2s 循环），停顿 2 秒以上则停止——不要让它一直闪，那会变成噪音

---

## 7. 动效

- 时长：悬停/按下 **120ms**，展开/折叠 **180ms**，模态进出 **200ms**
- 缓动：`cubic-bezier(0.2, 0, 0, 1)`（快出慢入，感觉利落）
- **必须**遵守 `prefers-reduced-motion: reduce`，此时所有过渡设为 0
- 进度条宽度变化用 `transition: width 200ms linear`，不要用弹簧动效——
  进度是数据，不是玩具

---

## 8. 布局

```
┌────────────────────────────────────────────────────────┐
│  顶栏  56px   logo · 全局速度 · 活动任务数 · 设置        │
├──────────┬─────────────────────────────────────────────┤
│ 侧栏     │  主区                                        │
│ 200px    │                                              │
│          │  工具条：筛选(全部/下载中/已完成/失败) + 新建   │
│ 全部     │  ─────────────────────────────────────────── │
│ 下载中   │  任务列表（虚拟滚动，行高 72px）              │
│ 已完成   │                                              │
│ 失败     │                                              │
│          │                                              │
│ 设置     │                                              │
└──────────┴─────────────────────────────────────────────┘
```

- 窗口最小 **880×560**；小于 1000px 宽时侧栏收成 48px 纯图标
- 任务行高 **72px** 固定：文件名一行、进度条一行、元数据一行
- 文件名过长从**中间**省略（`very-long-file…v2.zip`），
  因为扩展名比中间那串哈希更有信息量

---

## 9. 空状态与错误态

**空状态**（还没有任何任务）是用户看到的第一屏，不能只写"暂无数据"：

- 一个线条风格的图标（下载箭头落入托盘），48px
- 一句引导："把下载链接粘贴到这里" + 一个主按钮"新建下载"
- 说明可拖入链接 / 会自动读取剪贴板

**错误态**必须给出可操作的信息：

- ❌ 差：`Error: 403`
- ✅ 好：`服务器拒绝了请求（403）· 可能需要登录或该链接已失效` + 「重试」按钮

**失败的任务排在列表顶部**，不要按时间顺序埋下去。

---

## 10. 无障碍与键盘

| 操作 | 快捷键 |
|---|---|
| 新建下载 | `Ctrl+N` |
| 聚焦搜索 | `Ctrl+F` |
| 暂停/继续选中 | `Space` |
| 删除选中 | `Delete` |
| 全选 | `Ctrl+A` |
| 关闭弹层 | `Esc` |

- 所有可交互元素必须可 Tab 到达，且焦点环可见
- 图标按钮必须带 `aria-label`
- 进度条用 `role="progressbar"` + `aria-valuenow/min/max`
- 状态变化用 `aria-live="polite"` 播报（"下载完成：xxx.zip"），不要用 `assertive`

---

## 11. 自检清单

提交任何界面改动前，逐条确认：

- [ ] 没有写死的颜色，全部走 CSS 变量
- [ ] 间距只用了 4/8/12/16/24/32/48
- [ ] 会变化的数字用了等宽字体 + `tabular-nums`
- [ ] 状态不只靠颜色区分（有图标或文字）
- [ ] 键盘能走完全部功能，焦点环可见
- [ ] `prefers-reduced-motion` 下动效关闭
- [ ] 空状态和错误态都写了，不是"暂无数据"
- [ ] 窗口缩到 880×560 布局不塌
